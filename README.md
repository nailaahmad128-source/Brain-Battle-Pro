# Brain Battle Pro — by Mido Studio

Premium offline brain-training game for Android (Flutter). Package: `com.midostudio.brainbattlepro`. Built **only** by GitHub Actions — nothing is compiled locally.

**Games:** Memory Grid · Reflex Rush · Color Clash · Logic Chain · Math Blitz (10 adaptive mastery levels each)
**Systems:** Daily Challenge + streaks, XP/levels/rank titles, 18 achievements, Brain Score radar, local Hall of Fame, shareable score-card image, friend **challenge codes** (`BB-…`, same seeded puzzle, no backend/accounts), **9 languages** (English, اردو, العربية, हिन्दी, বাংলা, Español, Français, Português, Bahasa Indonesia — follows the phone's language or choose in Settings → Language; Urdu/Arabic switch the whole layout to right-to-left), sound + haptics, in-app Privacy Policy, AdMob + Google UMP consent.
Scores go through a `LeaderboardRepository` interface (only the local implementation exists; no online leaderboard is claimed or shown).

## 1. Push to GitHub (Termux)
```bash
pkg install git unzip
unzip brain_battle_pro.zip && cd brain_battle_pro
git init -b main && git add . && git commit -m "Brain Battle Pro 1.0"
git remote add origin https://github.com/<you>/<repo>.git && git push -u origin main
```
`android/` is generated by the workflow on every run (and patched: targetSdk/compileSdk 36, minSdk 24, AdMob app id, signing, no backup, no cleartext).

## 2. First run
Actions → **Android CI & Release** runs: format check → analyze → tests → **test APK** (debug-signed, Google *test* ads) uploaded as `brain-battle-pro-TEST-apk`.
If "Check formatting" fails, run the **Format code** workflow once (it commits `dart format`), then re-run. This project was written without a Flutter SDK available, so expect to iterate on the first CI run: send the log and fix.

## 3. Secrets & variables (Settings → Secrets and variables → Actions)
| Name | Type | Purpose |
|---|---|---|
| `KEYSTORE_BASE64` | secret | upload keystore, base64 (`base64 -w0 upload.jks`) |
| `KEYSTORE_PASSWORD`, `KEY_PASSWORD`, `KEY_ALIAS` | secret | keystore details |
| `ADMOB_APP_ID` | secret | `ca-app-pub-…~…` (goes into AndroidManifest) |
| `ADMOB_BANNER_ID`, `ADMOB_INTERSTITIAL_ID`, `ADMOB_REWARDED_ID` | secret | ad unit ids `ca-app-pub-…/…` |
| `PRIVACY_EMAIL` | variable | contact shown in the in-app policy |
| `VERSION_CODE_OFFSET` | variable (optional) | added to the run number to form `versionCode` |

Create the upload key (any machine with Java): `keytool -genkeypair -v -keystore upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload`. **Never commit it; back it up offline.** Play App Signing keeps the real app-signing key with Google, so a lost upload key can be reset via Play support.

Ad id rules: debug builds and the CI test APK use Google test ids. A release build uses **only** your secrets; if one is missing the release job refuses to run. Test ids are never used in a production AAB.

## 4. Build the signed AAB
Actions → Android CI & Release → **Run workflow** → tick *release* (or push a tag like `v1.0.0`). The job verifies all secrets, builds an obfuscated AAB, verifies it is **not** debug-signed, audits the merged permissions, and uploads `brain-battle-pro-release-aab` (AAB + R8 `mapping.txt` + Dart `symbols`). `versionName` comes from `pubspec.yaml`; `versionCode` = run number (+offset), so it always increases.

## 5. Upload to Google Play
Play Console → app → Testing → Closed testing → Create release → upload the `.aab` → accept Play App Signing → add release notes → roll out. Complete the forms listed in `play_store/04_prelaunch_checklist.md`. Documents: `play_store/` (listing, ads/content rating/app access, Data Safety, checklist, graphics) and `website/privacy.html` (host publicly; replace `CONTACT_EMAIL_HERE`).

Status of what has/hasn't been verified: `play_store/00_PROJECT_STATUS.md`.

## Languages
Text lives in `lib/l10n/strings.dart` (English text is the key; one map per language). To add a language: add `('tr', 'Türkçe')` to `kLanguages` and a `'tr': {...}` map with the same keys — a unit test fails if any key or `{placeholder}` is missing. Missing keys fall back to English. The privacy policy body stays in English (legal text, needs a professional translation); a translated summary is shown above it. Please have native speakers proofread the translations before release.
